# freshprints.dev — Full Site Audit (2026-07)

> Read-only recon pass. No source files were modified. Findings are grouped by area,
> each tagged `[SEVERITY] [EFFORT: S/M/L]` with a one-line recommended fix direction.
> Scope: entire site + admin dashboard (read-side PW metrics included); Pantheon Wars
> gameplay excluded per audit brief.
>
> Evidence basis: full production build (`vite build`, clean, 5.7s), file-level review of
> routing, all four themes, admin dashboard + its API queries, tracking pipeline,
> contact/email flows, data files, and public asset weights.

---

## Executive Summary

The site is in genuinely good structural health: the four-theme architecture is cleanly scoped (`[data-ui]` tokens, zero leakage found), routing is coherent, lazy-loading of page chunks works, the Blobert pipeline is well-hardened (validation → cache → rate limit → cap → AI → log), and the admin/game auth systems are correctly separated. The biggest problems are not code rot but **conversion leaks and first-load weight**. The `/hire` page — the site's flagship conversion surface with a cinematic hero, live stats, and a paid AI mascot — has **zero inbound links from any nav, footer, hub node, terminal command, or sitemap in any theme**; only Blobert himself can send a visitor there. The Store's six external products all link to `https://gumroad.com/l/placeholder`, so every BUY click dead-ends. On performance, the `/` splash statically pulls the 868 KB three.js chunk for a particle background, every visitor downloads ~13 Google Font families (five themes' fonts, partially double-loaded), and portfolio thumbnails are 1.5–2.7 MB PNGs with no `loading="lazy"` anywhere. Documentation drift is the top code-quality risk: `docs/PROJECT_REFERENCE.md` still claims 8/12 serverless functions when **11 of 12 are now used** — one slot remains, and decisions are being made against stale numbers. The admin dashboard is functional and well-organized, but its 25 aggregate queries re-run every 30 s (even in hidden tabs) and several scan all-time data unbounded; a small rollup + consolidation pass would future-proof it. Quick wins here are unusually cheap: five of the top ten items are one-line or one-file changes.

## 1. Code Quality & Redundancy

**1.1 [HIGH] [S] — Serverless function count is 11/12, docs say 8/12.**
`api/` now contains: contact, track, auth/admin, auth/check, auth/logout, auth/moderator, auth/reset, admin/overview, games/pantheon-wars/auth, games/pantheon-wars/game, games/pantheon-wars/titan-cron. `docs/PROJECT_REFERENCE.md:18,103,750` and CLAUDE.md still say "8 used, 4 slots remain."
→ Fix: update both docs to "11/12, ONE slot remains"; consider merging the three tiny `api/auth/*.js` admin-session files into one `?action=`-routed file to reclaim 2 slots (same pattern already used by moderator.js).

**1.2 [HIGH] [M] — `docs/PROJECT_REFERENCE.md` (2026-05-14) is materially stale.**
Wrong: function count (8 vs 11), Funky "stub, hidden" (complete, visible), Pantheon theme "stub" (complete, game-only), Beat Beaters lane map (says W/A/S/D/I/J/K/L; actual is A/S/D/F/Space/J/K/;), PvP "not built" (built, has log page), Temples/Township/Titan/Dungeons/Alliance/Codex/Chat all missing, no mention of /hire, Blobert, moderator system, password reset, Pusher, or the two Titan crons in vercel.json.
→ Fix: regenerate the reference doc from current code; it's the stated "read before touching code" doc and currently teaches wrong facts.

**1.3 [MED] [M] — STATUS_COLORS duplicated 5× with inconsistent coverage.**
`StandardCard.jsx`, `StandardPortfolio.jsx:27`, `StandardProjectPage.jsx:19`, `StandardLab.jsx:9`, `StandardLabExperiment.jsx:22` (+ Digital `Badge.jsx`). The Lab copies are missing `AVAILABLE`/`PRODUCTION`/`IN_DEVELOPMENT` keys the others have — a new status renders unstyled in some views. CLAUDE.md even documents "add to all four" as process.
→ Fix: single `src/utils/statusColors.js` export; the per-file maps become one import (~60 LOC removed, drift eliminated).

**1.4 [MED] [S] — Tailwind CSS is installed and imported but unused.**
`@import 'tailwindcss'` in `src/styles/global.css:2` injects preflight+theme, yet zero Tailwind utility classes exist in any JSX (verified by grep); `tailwind.config.js` is a v3-style config that Tailwind v4's Vite plugin doesn't read without `@config`.
→ Fix: remove the import, the two tailwind deps, and `tailwind.config.js` — after confirming nothing relies on preflight resets (global.css has its own reset).

**1.5 [MED] [S] — Dead components: `src/components/layout/Footer.jsx` and `src/components/media/VideoCard.jsx`.**
Zero imports anywhere (grid rendering moved into `VideoGrid`; Standard/Retro/Funky have their own footers).
→ Fix: delete both; also delete empty `public/models/` and `public/fonts/` dirs.

**1.6 [MED] [S] — `api/contact.js` email branches lack validation and escape nothing.**
`type: 'contact'` destructures `message` and calls `message.replace(...)` with no existence check (missing field → 500); all fields (`name`, `email`, `topic`, `message`, intake fields) are interpolated raw into email HTML — a submitter can inject arbitrary HTML/links into mail rendered in Kyle's inbox. No rate limiting on email-sending types (Blobert branch is well-protected; the email branches aren't), so a bot can burn Resend quota.
→ Fix: per-type required-field validation, HTML-escape all user strings, add a simple honeypot field + per-IP hourly cap.

**1.7 [MED] [S] — Page switchers statically import both theme variants.**
Every thin switcher (`src/pages/About.jsx` etc.) imports Digital AND Standard variants eagerly, so each route chunk ships both implementations to every user (e.g. `About` chunk = 31.9 KB carrying `DigitalAbout` + `StandardAbout`; a visitor only ever runs one). ~40–50 % dead weight per page chunk.
→ Fix: `lazy(() => import(...))` per variant inside the switcher (one Suspense already wraps routes).

**1.8 [MED] [S] — Repo clutter from game tooling at the project root.**
`preview/` (135 committed sprite-slice debug PNGs, 17 MB), `slice_sprites.py`, `scripts/check_sprites.py`, `clean_norse_bg.py`, `strip_bg_targeted.py`, `strip_white_bg.py`, `trim_buildings.py`, `alliance-recon.md`, `gdd-recon.md`, `PANTHEON-WARS-GDD-v2.md` at root.
→ Fix: move docs into `pantheon_wars/docs/`, move/delete sprite tooling + `preview/` (outputs are reproducible).

**1.9 [MED] [S] — `ThemeProvider` accepts and persists arbitrary theme IDs.**
`readInitialTheme()` (`src/themes/ThemeProvider.jsx:22`) trusts any `?ui=` value except `pantheon`; `?ui=xyz` sets `data-ui="xyz"` (no tokens match → unstyled page) and then `localStorage.setItem('fp-theme','xyz')` makes it sticky across visits. Same for `?mode=`.
→ Fix: validate the param against `themeIds` (registry already exports it) before accepting.

**1.10 [LOW] [S] — `sessions.duration_seconds` is a dead column.**
Schema defines it; nothing ever writes it (`api/track.js` only updates `page_count`/`last_seen_at`). Duration data actually lives in `time_on_page` events.
→ Fix: either compute `duration = last_seen_at - started_at` in queries and drop the column, or update it in track.js.

**1.11 [LOW] [S] — Tracker default context claims `digital`.**
`Tracker.js:10` initializes `{ uiTheme: 'digital' }` though the site default is `standard`; any flush before `AutoTrackers` mounts mislabels theme.
→ Fix: default to `'standard'` or `null`.

**1.12 [LOW] [S] — Admin chart boilerplate duplicated across 3+ files.**
`TOOLTIP_STYLE`, `TICK`, `GRID`, td styles, and pie-legend markup are copy-pasted in `AdminOverview.jsx`, `SiteAnalytics.jsx`, `GameMetrics.jsx` (legend also re-implemented inline in SiteAnalytics).
→ Fix: extract `src/components/admin/chartTheme.js` + a shared `<PieWithLegend>` (~120 LOC saved).

**1.13 [LOW] [S] — Hardcoded hex values and `'IBM Plex Mono'` strings throughout admin components.**
Violates operating rule 6/15 (tokens for every color/font). Admin-only surface, so cosmetic risk is low, but the accent hexes (`#FFB347`, `#8B5CF6`, `#F59E0B`) duplicate the category color map.
→ Fix: reference `var(--font-mono)` and add the accent hexes to a shared constants file when touching these files next.

**1.14 [LOW] [S] — `api/track.js` leaks internals and trusts input size.**
Returns `detail: err.message` to the client on failure; accepts an unbounded `events[]` array (a hostile client can post thousands of rows per request) and any `event_type` string.
→ Fix: drop `detail`, cap `events.length` (e.g. 50), allowlist event types.

**1.15 [QUESTION] — `src/sound/packs/pantheon.js`, `MusicManager`, `AmbienceManager` are imported globally in `main.jsx` / `App.jsx`.**
They're game infrastructure but load in the site's main bundle. Intentional (shell needs them on direct game-URL entry) or candidates to lazy-init inside `PantheonWarsShell`? Listed as a question, not a finding.

## 3. Performance & Bundle

Build snapshot (gzip): `react-three-fiber` chunk **868.75 KB (234 gz)**, `index` **513.73 KB (153.5 gz)**, `AreaChart`/recharts **352.8 KB (106 gz)**, `Admin` 156 KB (35 gz), single CSS 48.7 KB. Everything route-level is lazy-loaded — good baseline.

**3.1 [HIGH] [M] — three.js loads on the `/` splash for every visitor.**
`Landing.jsx:6` statically imports `ParticleField` (react-three-fiber + three), so the 868 KB chunk is on the critical path of the site's entry page — to render background particles behind three lines of text. The Hub legitimately needs it; the splash doesn't.
→ Fix: lazy-mount ParticleField after first paint (`Suspense fallback={null}`), or replace the splash/portfolio instances with a 2D-canvas particle field and keep r3f for the Hub only.

**3.2 [HIGH] [S] — Multi-MB thumbnails with zero image lazy-loading.**
24 `<img>` tags site-wide, none with `loading="lazy"`. Portfolio thumbnails: pantheon 2.7 MB, jogger 2.3 MB, beatbeaters 2.3 MB, predictinator 2.1 MB, lexis 1.8 MB, plutus 1.5 MB — the portfolio grid alone approaches ~13 MB of PNG. Gallery images similar (`Concept Map.png` 2.7 MB).
→ Fix: batch-convert thumbnails/gallery images to WebP at display resolution (~100–250 KB each) + add `loading="lazy" decoding="async"` to every non-hero img.

**3.3 [HIGH] [S] — Font loading: ~13 families, partially double-loaded, all render-blocking.**
`main.jsx` bundles all five themes' `fonts.css` `@import`s (Bebas/IBM Plex/DM Sans, Bricolage/Geist/Geist Mono, Press Start/VT323, Cinzel/Cormorant, Unbounded/Outfit/Space Mono) into the single CSS file — five chained Google-Fonts requests for every visitor regardless of theme. `index.html:36-38` additionally `<link>`s Geist, Press Start, VT323, Cinzel, Cormorant, Rajdhani, Unbounded, Outfit, Space Mono — duplicating most of them.
→ Fix: keep only the active theme's fonts in the head (the flash-prevention script already knows the theme pre-paint — it can inject the right `<link>`), drop the per-theme `@import`s or load them lazily on theme switch.

**3.4 [MED] [S] — model-viewer CDN module loads on every page.**
`index.html:59` loads model-viewer 3.4 globally; only the CAD Lab experiment and project pages with `.glb` models use it.
→ Fix: inject the script on demand from `ModelViewer.jsx`/`CADViewer.jsx` (one-time dynamic `import()`/script tag).

**3.5 [MED] [M] — Main `index` chunk (513 KB / 153 gz) carries all theme layouts + framer-motion eagerly.**
`App.jsx` statically imports Standard/Retro/Funky layouts, Blobert skins registry, game ChatBar/ChatContext (Pusher client), and sound managers into the shared bundle.
→ Fix: lazy-load Retro/Funky layouts (only one theme is active) and move ChatBar/pusher-js behind the game shell; expect ~30–40 % index-chunk reduction.

**3.6 [MED] [S] — Admin polls 25 aggregate queries every 30 s, forever, even in hidden tabs.**
`usePolling` (src/hooks/usePolling.js) has no `visibilitychange` pause; the Overview tab runs `/api/admin/overview` (11 queries) + `admin_metrics` (14 queries) per tick. A forgotten admin tab = ~3,000 queries/hour against Neon.
→ Fix: skip ticks while `document.hidden`, refresh on focus.

**3.7 [MED] [S] — Several overview queries scan all-time data and grow unbounded.**
`api/admin/overview.js`: `pageViewsTotal`, `topPaths` (GROUP BY over every page_view ever), `deviceBreakdown`/`browserBreakdown`/`topReferrers` (all sessions ever). Fine today; degrade linearly forever, and they re-run every 30 s.
→ Fix: time-bound to 30/90 days or read from a daily rollup (see §Admin/PW Metrics); add composite index `events(event_type, timestamp)` for the today/30-day filters.

**3.8 [MED] [S] — `api/track.js` inserts events one-per-round-trip.**
The per-event `INSERT` loop means a 20-event flush = 20 sequential Neon round trips inside one function invocation.
→ Fix: single multi-row INSERT (neon serverless supports `sql.transaction` or a values-list build).

**3.9 [LOW] [S] — Buffered events are attributed to the flush-time path.**
`Tracker.flush()` sends one `path: window.location.pathname` for the whole batch; events buffered on page A but flushed after navigating to B are recorded under B (the true path sits unused in `event_data`). Top-paths numbers are systematically smeared toward destination pages.
→ Fix: `api/track.js` should prefer `ev.data.path` when present for the `path` column.

**3.10 [LOW] [S] — recharts chunk (352 KB) is pulled by lab experiments as well as admin.**
Predictinator/Plutus lab widgets import recharts; acceptable since it's split and cached, but it makes those Lab pages ~106 KB gz heavier than they look.
→ Fix: nothing urgent; consider lightweight sparkline SVGs for the lab widgets if Lab bounce weight matters.

**3.11 [LOW] [S] — `vercel.json` headers are dated.**
`X-XSS-Protection` is deprecated (removed from modern browsers); no `Referrer-Policy` or `Permissions-Policy`.
→ Fix: swap in `Referrer-Policy: strict-origin-when-cross-origin` + minimal `Permissions-Policy`; keep `X-Frame-Options`/`nosniff`.

**3.12 [LOW] [S] — Blobert admin session list groups all `hire_buddy_logs` by `session_id` with no session index.**
Indexes exist on `(ip_hash, created_at)` and `(created_at)` only; the 90-day purge bounds the table, so this is future-proofing.
→ Fix: add `idx_hire_buddy_logs_session (session_id, created_at)` next time migrations run.

**3.13 [NOTE — game-adjacent, read-side only] — Deploy weight is dominated by game art.**
`public/pantheon_wars_assets` = 197 MB (township building PNGs are 2.3–2.9 MB each); `dist/` output is 276 MB per deploy. No site-side action required and gameplay assets are out of scope — noted only because any future asset-compression pass (lossless PNG→WebP at same resolution) would not change player-facing behavior while cutting deploy/CDN weight ~5–10×.

## Admin Dashboard / PW Metrics (read-side recommendations only)

**Current shape:** `admin_metrics` = 14 parallel queries returning point-in-time snapshots; site overview = 11 parallel queries; Overview tab fetches both; everything re-polled every 30 s.

1. **Split a cheap "pulse" endpoint from the heavy detail queries.** Overview needs 6 numbers (visitors, views today, players, active 24 h, PvP today, chat today) — serve them from one `action=summary` doing 6 indexed COUNTs, and fetch the 25-query detail payloads only when their tab is opened (and on manual refresh). Cuts steady-state admin query volume ~80 %.
2. **Add a daily rollup instead of all-time scans.** A `site_daily_stats` (day, views, unique_visitors, sessions, top_paths jsonb) + `pw_daily_stats` (day, signups, active_players, quests_completed, pvp_fights, chat_messages, total_drachma) row written once per day makes every "30-day chart" a 30-row read and — more importantly — **gives you history you currently can't reconstruct** (there is no way today to chart player growth or drachma inflation over time; totals are only "now"). No new function file needed: the existing `titan-cron.js` already fires twice daily and can take an extra `?event=rollup` branch, or the rollup can run lazily on first admin request of the day.
3. **Time-bound the unbounded queries.** `topPaths`, `deviceBreakdown`, `browserBreakdown`, `topReferrers`, `pageViewsTotal`, `pvpFightsTotal` scan whole tables on every poll. Windowing to 30/90 days (with the all-time number moved to the rollup) keeps latency flat as tables grow. Add `events(event_type, timestamp)` composite index — current single-column indexes force a choice.
4. **Consolidate paired counts.** `pvpFightsToday`/`pvpFightsTotal` → one query with `COUNT(*) FILTER (WHERE created_at > NOW() - INTERVAL '24 hours')`; same trick fits several of the 14.
5. **Level distribution readability.** At 100 levels the per-level bar chart becomes noise; bucket server-side (1–9, 10–19, …) or render cumulative. Also consider a median (`percentile_cont(0.5)`) next to `avgDrachma` — averages are whale-dominated in MMO economies.
6. **"Active players (24 h)" overcounts.** It's derived from `pw_player_stats.last_updated`, which regen updates on many read paths — any player whose row was touched counts as active. Recommend counting actors instead: distinct users in combat log/quest completions/chat in 24 h, or a dedicated `last_action_at` set only on POST actions.
7. **Fold GameMetrics gaps in cheaply:** new-signups-per-day line (from `pw_users.created_at`, already indexed by PK date semantics), quests/day (needs the rollup — `pw_quest_progress` stores only totals), and glory leaders next to the drachma top-10 (same query shape).
8. **Blobert tab:** solid as built (cache/fuzzy/ai split, cap gauge, transcripts). Add `hire_buddy_logs(session_id)` index before traffic grows, and consider surfacing "AI answers that came from unanswered-FAQ territory" (ai-answered first messages) as a seed list for new FAQ rows — it turns spend into cache hits.
9. **UX:** show query window labels on cards ("24 h", "all-time") — today "PvP Fights Today" sits next to unlabeled all-time totals; and the SYNC/refresh header pattern is good — wire the per-tab `lastUpdated` for HireStats/Titan/Moderator tabs too (currently only Overview/Analytics/Game/Blobert report it).

## Do Not Touch (looks odd, is intentional)

- **Digital-name token aliases** inside `standard/`, `retro/`, `funky/tokens.css` — deliberate bridge so shared components (IntakeWizard, admin) render in all themes.
- **`src/styles/tokens.css` stub** — intentionally empty; real tokens live per-theme.
